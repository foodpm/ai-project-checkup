# 海外网站合规审计与上线检查清单

> 检查项编号：CO-01 至 CO-06（六项高风险）、CO-P0-01 至 CO-P2-06（上线门禁）
>
> 文档版本：1.0 · 更新日期：2026-11-08
>
> 思路来源：X 帖子 <https://x.com/liangzhu_ai/status/2113894763221176515?a=_PQxdz11i6zyXb8fjTg&s=46>。本文已改写为通用模板，不含任何具体运营主体、域名或账号信息。
>
> 适用对象：面向海外用户的网站、Web App、SaaS、订阅制产品、含用户内容的平台
> 文档用途：源码审计、整改验收、上线门禁、定期复审

## 0. 使用方式与结论口径

这是一份**通用检查模板**，不针对任何特定主体。仅凭清单打勾不能证明合规，也不能声称六项风险已经修复；必须结合项目的实际源码、配置、页面与后台记录逐项取证。

每项检查只能使用以下状态之一：

| 状态 | 含义 |
|---|---|
| 通过 | 有代码、配置、截图或后台记录证明控制已生效 |
| 不通过 | 已发现缺口，必须整改 |
| 待核验 | 尚未取得足够证据 |
| 不适用 | 有明确理由证明该规则不适用，并已留档 |

禁止把“页面上写了声明”“隐私政策提到”“供应商后台有开关”单独视为通过。必须同时验证实际数据流、服务端行为、用户界面和留存证据。

## 1. 六项法律风险总表

| 编号 | 风险 | 默认等级 | 主要适用规则 |
|---|---|---:|---|
| CO-01 | 注册环节缺少年龄验证 | P0 | COPPA、GDPR、UK GDPR |
| CO-02 | 字体由第三方远程托管 | P1 | GDPR/ePrivacy、CCPA/CPRA、合同与隐私披露 |
| CO-03 | 会话重放未经同意或捕获敏感输入 | P0 | GDPR/ePrivacy、CCPA/CPRA、HIPAA 等场景规则 |
| CO-04 | 营销邮件缺少退订链接或邮政地址 | P0 | CAN-SPAM、ePrivacy、UK PECR |
| CO-05 | 订阅按钮附近未直接披露续订条款 | P0 | ROSCA、FTC Act、各州自动续订法、欧盟消费者法 |
| CO-06 | 未注册 DMCA 指定代理 | P1 | 17 U.S.C. § 512、37 C.F.R. § 201.38 |

## 2. 六项整改规格与验收

### CO-01 注册年龄验证

#### 必须实现

1. 在创建账号、收集邮箱、姓名、手机号、营销同意或其他个人数据之前完成年龄判定。
2. 年龄输入必须中立，不得默认成年，不得用诱导性文案引导用户虚报年龄。
3. 年龄判定必须在服务端完成；前端校验只能改善体验，不能作为安全边界。
4. 未达到目标市场最低年龄的用户不得创建账号，不得进入后续个人数据收集流程。
5. 如业务允许儿童使用，必须按 COPPA 取得可验证父母同意（VPC），并执行数据最小化、家长访问和删除机制。
6. 年龄信息只保留实现目的所需的最少内容。建议保留“年龄段/是否达标”和判定时间，不长期保存完整出生日期。
7. 所有注册入口必须覆盖：邮箱注册、Google/Apple/其他 SSO、邀请注册、移动端注册、API 注册。
8. 已存在账号如被确认属于未达年龄用户，应有停用、删除和申诉流程。

#### 市场门槛

| 市场 | 默认规则 | 实施要求 |
|---|---|---|
| 美国 | COPPA 关注 13 岁以下儿童 | 面向儿童、混合受众或实际知悉收集儿童数据时，收集前提供通知并取得 VPC |
| 欧盟/EEA | GDPR 同意年龄默认 16 岁 | 成员国可降至不低于 13 岁；按用户所在国配置门槛并核实父母同意 |
| 英国 | 同意场景通常为 13 岁 | 同时按 ICO 儿童设计规范，对可能被 18 岁以下用户访问的服务做风险评估 |
| 其他市场 | 逐市场确认 | 不得用单一全球门槛替代本地法律分析 |

#### 建议文案

> 请确认你的出生日期。我们使用该信息判断你能否创建账号，并仅保留必要的年龄结果。未达到适用年龄的用户不能创建账号。

#### 验收测试

- 用低于门槛、刚好达到门槛、高于门槛三组日期测试，服务端结果正确。
- 未达门槛请求不能创建用户、会话、订阅或营销联系人记录。
- 绕过前端直接调用注册 API 时仍被拦截。
- 所有 SSO 和邀请入口执行相同规则。
- 日志、分析事件和错误上报中不出现完整出生日期。
- 儿童路径如启用，能证明 VPC、家长权利和数据删除流程可运行。

### CO-02 字体自行托管

#### 必须实现

1. 全量清点网页、样式表、邮件模板、组件库和第三方页面中的字体请求。
2. 删除 Google Fonts、Adobe Fonts、Typekit、字体 CDN 等远程字体依赖。
3. 将合法取得的字体文件转为或下载为本地 WOFF2，放在自有域名或受控静态资源域名。
4. 保留字体许可证、授权范围、来源、版本和再分发证明。
5. 更新 CSP，默认只允许自有字体源：

```http
Content-Security-Policy: font-src 'self';
```

6. 邮件客户端通常不支持可靠的自定义 Web Font，营销邮件应使用安全字体回退，避免为字体引入远程跟踪资源。
7. 隐私政策中如曾披露字体供应商，应同步更新；供应商 DPA 和跨境传输清单也要复核。

#### 验收测试

- 页面加载时不再请求 `fonts.googleapis.com`、`fonts.gstatic.com` 或其他远程字体域名。
- 删除所有远程字体 `@import`、`preconnect`、`preload` 和 CSS 引用。
- 断网、第三方域名被拦截时字体仍能正常加载。
- CSP 报告中没有字体违规，也没有新增远程字体回退。
- 仓库中存在字体许可证清单，且生产字体文件与授权版本一致。

### CO-03 会话重放

#### 默认方案

**默认关闭会话重放。** 会话重放会记录页面交互、输入、点击路径和可能的敏感信息，不应在没有明确业务必要性和合规依据时默认启用。

#### 如确需启用

1. 在会话重放 SDK 加载前取得明确、可撤回的同意；不能在 SDK 已经开始录制后才弹窗。
2. 默认屏蔽全部输入框，不应依赖逐个字段配置。
3. 支付、密码、登录、验证码、健康、身份证明、儿童数据、私信和账户设置页面应完全排除录制。
4. 禁止在用户提交前捕获按键内容、剪贴板、文件上传内容或表单原文。
5. 使用供应商提供的最严格屏蔽策略，并增加业务级 `data-sensitive` 标记作为第二层保护。
6. 明确保留期、访问人员、审计日志、删除流程和供应商子处理者。
7. 签署 DPA，确认数据存储地区、跨境传输机制和执法请求处理方式。
8. 用户撤回同意后立即停止录制，并按政策删除或匿名化已有录像。
9. 不得把会话重放数据用于广告画像或与营销数据拼接。

#### 配置示意

具体参数必须按实际 SDK 文档调整，不能直接照搬：

```js
// 仅示意：默认屏蔽所有输入，并排除敏感区域。
sessionReplay.init({
  maskAllInputs: true,
  maskTextSelector: "*",
  blockSelector: "[data-sensitive], .payment, .auth, .health",
});
```

#### 验收测试

- 未同意前网络面板中不存在会话重放 SDK 请求或录像上传。
- 用测试信用卡号、密码、邮箱和验证码做金丝雀测试，录像中均不可见。
- 支付、登录、健康等页面完全不产生录像。
- 撤回同意后不再产生新录像。
- 后台只能由授权人员访问，且访问有日志。
- 保留期到期后数据确实被删除。

### CO-04 营销邮件退订与邮政地址

#### 每封商业营销邮件必须具备

1. 清晰的发件人身份和邮件性质说明。
2. 清晰显著的退订入口。
3. 有效的实体邮政地址。
4. 可正常工作的 `List-Unsubscribe` 邮件头。
5. 支持一键退订时配置 `List-Unsubscribe-Post: List-Unsubscribe=One-Click`。
6. 退订不要求登录、付费、拨打电话、填写额外个人信息或说明原因。
7. 退订请求进入统一 suppression list，并同步到所有邮件供应商和业务系统。
8. CAN-SPAM 的法定最迟处理期限是 10 个工作日；建议即时或 24 小时内生效。
9. 邮件模板、事务邮件中夹带的促销内容、自动化营销流程和再营销序列都要检查。
10. 欧盟/英国等市场不能仅依赖 CAN-SPAM；电子营销通常还需要符合本地同意规则。

#### 推荐邮件页脚

> 你收到此邮件是因为你订阅了 [品牌] 的更新。
> [退订全部营销邮件] · [管理偏好]
> [公司法定名称]，[有效实体邮政地址]
> [隐私政策] · [联系方式]

#### 验收测试

- 对每类营销模板实际发送测试邮件，确认链接和邮件头均有效。
- 退订后不再收到该类别营销邮件。
- 退订状态在 CRM、邮件平台和自动化流程之间一致。
- 退订页面不要求额外个人数据。
- 邮政地址真实、可收件、与发送主体一致。
- 邮件中的追踪像素和链接追踪已纳入隐私同意和披露。

### CO-05 订阅续订条款

#### 必须紧邻订阅按钮展示

在用户输入支付信息前，并在购买按钮附近直接显示：

- 当前收费金额和币种。
- 计费周期，例如每月、每年或每 4 周。
- 是否自动续订。
- 首次扣费日期和下一次续费日期。
- 试用期结束后的价格和扣费时间。
- 取消方式及可取消的最晚时间。
- 价格变更规则。

示例：

> 年费 US$120，今天收取 US$120。之后每 12 个月自动续订 US$120，直到取消。可随时在“账户 > 账单 > 取消订阅”在线取消，无需致电。

#### 同意与取消

1. 自动续订同意不得预勾选，不得捆绑在隐私政策或通用条款中。
2. 取得用户明示知情同意后，才能扣款。
3. 保存条款版本、展示时间、按钮文案、用户操作和同意记录。
4. 提供无需电话、邮件审批或人工挽留的在线取消路径。
5. 取消完成后发送确认，说明服务何时终止、是否仍可使用、是否还有后续扣款。
6. 试用转付费前建议发送提醒，但提醒不能替代购买时的清晰披露。
7. 退款权、欧盟撤回权和取消订阅是不同概念，不能用一个“取消”流程混同处理。

#### 法律提醒

2025-07-08 美国第八巡回法院撤销了 FTC 的联邦 Negative Option Rule。这不代表自动续订不再受监管：ROSCA、FTC Act 和各州自动续订法仍可能适用。不要依据“联邦规则已撤销”而移除清晰披露、明示同意和简单取消机制。

#### 验收测试

- 在桌面和移动端首屏检查，续订条款无需展开、滚动到隐私政策或点击链接即可看到。
- 不勾选任何额外选项也能拒绝自动续订；若业务只提供自动续订，必须明确说明。
- 支付接口不能绕过前端同意状态直接扣款。
- 取消流程可从账户设置独立完成。
- 取消后收到确认，且不再产生新扣款。
- 试用、优惠价、价格上调、暂停和恢复均有测试用例。

### CO-06 DMCA 指定代理注册

#### 先澄清

DMCA 指定代理不是版权登记。它指定的是接收侵权通知的代理人。注册代理也不自动获得 § 512 安全港；还需满足通知删除、反通知、重复侵权者政策等条件。

#### 注册前准备

| 项目 | 要求 |
|---|---|
| 服务提供者法定名称 | 必须与法律主体一致 |
| 实际街道地址 | 通常不能使用 P.O. Box，例外需事先获批 |
| 公开别名 | DBA、品牌名、域名、App 名、常用搜索名 |
| 代理名称 | 个人、职位、部门或第三方服务机构 |
| 代理地址 | 街道地址或 P.O. Box |
| 代理电话 | 可联系 |
| 代理邮箱 | 建议使用专用 `dmca@` 邮箱 |

同一服务提供者只能指定一个代理；不同法律实体分别注册。

#### 操作步骤

1. 确认网站中哪些功能属于用户上传、存储或信息定位服务。
2. 确定实际运营主体的法定名称和街道地址。
3. 建立 `/dmca` 或 `/copyright` 公开页面，展示法定名称、地址、别名和代理联系方式。
4. 创建专用 `dmca@` 邮箱和工单队列，指定负责人和备份负责人。
5. 访问美国版权局 DMCA 指定代理系统：<https://dmca.copyright.gov/osp/login.html>。
6. 创建注册账号，选择或新增服务提供者。
7. 填写法定名称、街道地址、全部公开别名、代理姓名/组织、地址、电话和邮箱。
8. 核对公开页面信息与系统填写内容完全一致。
9. 支付当前费用（金额以版权局页面公布为准，历史为 US$6）并提交。
10. 保存确认页、收据、提交日期和目录搜索结果截图。
11. 在版权局公开目录中搜索并确认信息已生效。
12. 将续期日期加入日历：注册后三年到期前完成修订或重新提交。
13. 设置到期前 90、60、30、7 天的内部提醒，不依赖官方提醒邮件。

#### 注册后仍需完成

- 建立侵权通知接收、审核、下架和回复流程。
- 保存通知、下架时间、证据和沟通记录。
- 建立反通知流程及 10 至 14 个工作日的恢复规则。
- 制定并合理执行重复侵权者终止政策。
- 在用户条款中告知重复侵权政策和版权投诉方式。
- 对代理离职、公司改名、域名变更和地址变更及时更新注册。

#### 验收测试

- 公开页面无需登录即可访问。
- 页面信息与版权局目录完全一致。
- 向代理邮箱发送测试通知，工单成功创建并有负责人处理。
- 注册记录、收据和下次续期日期已归档。
- 实际执行过至少一次模拟下架、反通知和恢复流程。

## 3. 海外网站常见合规坑

| 风险领域 | 常见错误 | 最低控制 |
|---|---|---|
| 隐私政策 | 模板中的公司名、地址、邮箱、供应商与实际不一致 | 每次上线自动核对主体、联系方式、数据流和条款版本 |
| Cookie 与分析 | 用户在同意前已加载分析、广告像素、热图和会话重放 | 默认拒绝非必要脚本，取得同意后再加载，并提供同等明显的拒绝按钮 |
| 跨境传输 | 使用美国云服务但未做 SCC、DPF 或传输评估 | 维护供应商、数据类别、存储地区、传输机制和 DPA 清单 |
| 数据主体请求 | 只有邮箱，没有身份核验、时限和删除联动 | 建立访问、更正、删除、导出、限制和反对请求的工单流程 |
| 数据保留 | 日志、备份、营销名单和录像永久保存 | 为每类数据定义保留期、自动删除和备份删除规则 |
| CCPA/CPRA | 有“出售个人信息”但无退出链接，不识别 GPC | 提供 Do Not Sell/Share 入口、GPC 支持和收集时通知 |
| 儿童与青少年 | 只给成人条款，不检查 SSO、邀请和公开内容入口 | 统一年龄门槛、默认高隐私、限制广告画像和公开资料 |
| 暗黑模式 | 预勾选营销、隐藏费用、虚假倒计时、取消按钮难找 | 所有拒绝与同意选项同等明显；取消和购买路径对称 |
| 试用与退款 | 只写“可取消”，不说明何时扣费和如何取消 | 试用结束日期、转换价格、取消期限和退款政策在 CTA 附近展示 |
| 无障碍 | 只用颜色表达错误、键盘不可操作、弹窗无焦点管理 | 按 WCAG 2.2 AA 做自动化与人工测试 |
| 用户内容 | 无版权投诉、商标、诽谤、仇恨内容和 CSAM 流程 | 建立举报、审核、下架、申诉、执法留存和紧急升级机制 |
| 素材许可 | 图片、音乐、图标、代码和 AI 生成内容来源不明 | 建立素材台账，保存许可证、来源、生成记录和授权范围 |
| 邮件与短信 | 购买名单、预勾选同意、退订不同步、短信无 STOP | 保存同意来源和时间，统一 suppression list，支持 STOP/HELP |
| 税务 | 全球销售但未判断 VAT、GST、销售税和发票义务 | 按客户所在地、数字服务类型和收入阈值做税务登记评估 |
| 支付合规 | 受限业务、拒付率高、未启用 3DS/SCA | 核对支付商政策、账单描述、退款、拒付和强客户认证流程 |
| 安全 | 无 MFA、会话不过期、Cookie 缺 Secure/HttpOnly、无速率限制 | 做威胁建模、依赖扫描、密钥管理、日志脱敏和渗透测试 |
| 数据泄露 | 无响应手册，不知道 72 小时通知义务 | 建立发现、遏制、评估、通知、取证和复盘流程 |
| 条款版本 | 条款更新后无法证明用户同意的是哪个版本 | 条款版本化，保存展示时间、版本号和同意证据 |
| 本地化 | 只有英文条款，缺少德国 Impressum 等本地强制信息 | 按目标市场检查语言、公司信息、联系方式和当地消费者权利 |
| 欧盟撤回权 | 把取消订阅当作撤回权，数字内容例外处理错误 | 区分撤回、取消、退款；结账前披露并取得必要确认 |
| 广告宣传 | 虚假折扣、未披露付费评测、虚构用户评价 | 保存广告主张证据，披露联盟关系和付费合作 |
| 促销活动 | 抽奖、返现、推荐奖励未写规则和税务处理 | 发布完整活动规则、资格、截止时间、隐私和税务说明 |
| 制裁与出口 | 未筛查受制裁地区、受限制主体或受限产品 | 评估支付、IP、账户和客户筛查要求 |
| 平台内容规则 | UGC 平台只做 DMCA，不处理其他违法内容 | 建立 notice-and-action、透明度、投诉和重复违规处理机制 |

## 4. 上线门禁

### P0：未完成不得上线

- [ ] **CO-P0-01** 年龄判定在服务端生效，未达门槛用户无法创建账号。
- [ ] **CO-P0-02** 会话重放默认关闭；如启用，同意、输入屏蔽和敏感页面排除均已验证。
- [ ] **CO-P0-03** 每封营销邮件有可用退订链接和有效邮政地址。
- [ ] **CO-P0-04** 退订进入统一 suppression list，并能在 10 个工作日内停止发送。
- [ ] **CO-P0-05** 订阅 CTA 旁直接显示价格、周期、自动续订、扣费日期和取消方式。
- [ ] **CO-P0-06** 自动续订同意未预勾选，扣款前有明示知情同意记录。
- [ ] **CO-P0-07** 非必要 Cookie、分析、广告像素和会话重放在同意前不加载。
- [ ] **CO-P0-08** 隐私政策中的主体、地址、联系方式、供应商和数据流与真实情况一致。
- [ ] **CO-P0-09** 有可用的数据删除、访问和退订请求渠道。
- [ ] **CO-P0-10** 密码、支付、身份证明和儿童数据不会被写入普通日志或分析事件。

### P1：上线后 30 天内完成

- [ ] **CO-P1-01** 字体全部自行托管，许可证和 CSP 已验证。
- [ ] **CO-P1-02** DMCA 指定代理已公开并完成版权局注册。
- [ ] **CO-P1-03** DMCA 通知、反通知和重复侵权者流程已演练。
- [ ] **CO-P1-04** 供应商 DPA、跨境传输和子处理者清单已完成。
- [ ] **CO-P1-05** 数据保留期和自动删除任务已上线。
- [ ] **CO-P1-06** CCPA/CPRA 的 Do Not Sell/Share 与 GPC 已测试。
- [ ] **CO-P1-07** WCAG 2.2 AA 关键路径检查完成。
- [ ] **CO-P1-08** 数据泄露响应联系人和 72 小时流程已建立。

### P2：持续治理

- [ ] **CO-P2-01** 每季度复核 Cookie、像素、SDK 和字体域名。
- [ ] **CO-P2-02** 每季度复核营销 suppression list 和退订自动化。
- [ ] **CO-P2-03** 每半年复核订阅价格、试用、取消和退款流程。
- [ ] **CO-P2-04** 每年复核目标市场、税务、支付商政策和无障碍要求。
- [ ] **CO-P2-05** DMCA 注册到期前三年周期内持续维护，变更时立即修订。
- [ ] **CO-P2-06** 所有条款、政策和同意界面保留版本与变更记录。
